# Audit & Perbaiki SPPG

Audit menyeluruh repo Absensi SPPG. Tujuannya menemukan bug nyata, bukan mengulang
pemeriksaan yang sudah dikerjakan gerbang otomatis. Setelah itu temuan yang
disetujui user diperbaiki dan hasilnya diverifikasi.

## Latar yang wajib dipahami (repo ini)

- Satu basis kode, tiga target:
  - **Web**: Next.js di server, menulis ke libSQL lewat `src/app/api/**`.
  - **Desktop**: Tauri v2 + Rust, SQLite lokal, outbox yang disinkronkan langsung ke libSQL.
  - **Mobile**: Tauri Android, `output: "export"`.
- `web-desktop/` adalah **sumber kebenaran**. Salinan otomatis:
  - `bun run sync:mobile` menyalin `web-desktop/src/lib`, `src/types`, dan modul Rust di `mobile/scripts/sync-rust-modules.ts` (termasuk `desktop/payroll/` ke `mobile/.../payroll_admin/`).
  - Yang **TIDAK** disalin: `mobile/src/app/**` dan `mobile/src/components/**` (halaman dan komponen mobile ditulis terpisah), serta `mobile/src-tauri/src/lib.rs`, `build.rs`, `capabilities/`, `config.rs`, `secrets.rs`, `storage.rs`, `share.rs`, `payroll.rs`.
- Aturan proyek ada di `CLAUDE.md` root dan `web-desktop/AGENTS.md`. Baca dulu. Nomor aturannya dipakai untuk mengutip pelanggaran.
- Gerbang yang tersedia:
  - `bun run audit:schema`, `bun run audit:contract`, `bun run check:quick` (tanpa Rust).
  - `bun run check` (termasuk `cargo test`, sangat lama).
  - `cargo check --manifest-path web-desktop/src-tauri/Cargo.toml --tests` (kompilasi saja, ±2 menit pertama kali, ±40 detik inkremental).

## Instruksi

### Fase A: Audit

1. **Tanya cakupan bila belum jelas.** Seluruh repo, atau berkas/komponen tertentu? Kalau user menempelkan prompt audit tanpa berkas, anggap seluruh `web-desktop/` + `mobile/`.
2. **Jalankan gerbang murah dulu**, paralel. Hasilnya menunjukkan apa yang TIDAK perlu diaudit manual:
   - `bun run audit:schema` dan `bun run audit:contract` dari root.
   - Typecheck kedua workspace: `node_modules/.bin/tsc --noEmit` di masing-masing folder. Jangan `npx tsc`, itu mengunduh paket palsu.
   - `bun .claude/skills/audit-perbaiki-sppg/scripts/drift.ts` (salinan Rust identik?).
3. **Jalankan skrip pemeriksa skill ini**, lalu verifikasi setiap hit dengan membuka kodenya:
   - `scripts/command-guards.ts`: command tanpa `require_permission`. Login, reset password, dan status bootstrap memang sah tanpa sesi. Yang dicari adalah command mutasi atau baca data tanpa guard.
   - `scripts/ipc-args.ts`: argumen `invokeDesktop` harus camelCase. Objek bersarang sering muncul sebagai positif palsu.
4. **Telusuri checklist manual** (lihat bagian Checklist di bawah) dengan `grep` di **KEDUA** workspace, termasuk `mobile/src/app` dan `mobile/src/components`.
5. **Buktikan setiap temuan sebelum dilaporkan.** Baca fungsinya utuh, cari semua pemanggilnya, dan cek apakah ada guard di lapisan lain (CHECK constraint lokal, validasi di handler, guard di halaman mobile). Klaim numerik (pembulatan, overflow) dibuktikan dengan eksekusi kecil (`bun -e ...`) bila bisa. Yang belum terbukti ditandai eksplisit.
6. **Tulis laporan** dengan format di bawah. Tawarkan penerapan, jangan langsung mengubah kode kecuali user sudah meminta.

### Fase B: Perbaikan (setelah user memilih nomor temuan)

7. **Sebelum mengedit, grep setiap simbol yang akan diubah atau dihapus di seluruh repo**, termasuk `mobile/src/app`, `mobile/src/components`, `build.rs`, `capabilities/default.json`, dan `permissions/autogenerated/`. Menghapus command wajib menyentuh: fungsi, kedua `lib.rs`, kedua `build.rs`, kedua `capabilities/default.json`, berkas `permissions/autogenerated/<cmd>.toml`, dan gateway TS.
8. **Tanyakan dulu** (lewat pertanyaan pilihan dengan opsi yang direkomendasikan) untuk perubahan yang:
   - mengubah skema produksi (drop constraint, rebuild tabel),
   - menghapus fitur yang dipakai UI,
   - mengubah arsitektur (aturan 3 di `web-desktop/AGENTS.md`).
9. **Edit sumber di `web-desktop/`**, lalu jalankan `bun run sync:mobile`. Halaman atau komponen mobile yang punya bug sama diedit **terpisah** di `mobile/src/app` / `mobile/src/components`.
10. **Pakai helper yang sudah ada** sebelum membuat baru, misalnya `formatTanggalOperasional` (`src/lib/attendance/time-policy.ts`), `base_revision` (`operational.rs`), `require_session`/`require_permission` (`commands.rs`), dan pola `attendance_guard` batch di `turso.rs`.
11. **Tinggalkan satu tes kecil** untuk logika non-trivial (uang, keamanan, parser). Taruh di modul `#[cfg(test)]` Rust yang sudah ada atau di berkas `*.test.ts` yang sudah ada.
12. **Verifikasi bertahap:**
    - `bun run sync:mobile`, lalu `drift.ts` harus melaporkan semua identik.
    - `bun run check:quick` dari root. Bila lint gagal karena format di mobile, jalankan `mobile/node_modules/.bin/biome format --write <berkas>`, bukan `npx biome`.
    - `cargo check --manifest-path web-desktop/src-tauri/Cargo.toml --tests`.
    - **Tanya user** sebelum `bun run check` / `cargo test`, karena prosesnya lama. Bila user meminta berhenti, hentikan task latar dan juga matikan proses `cargo`/`rustc` yang tersisa (PowerShell: `Get-Process cargo,rustc | Stop-Process -Force`).
13. **Laporkan hasil** dengan format di bawah: apa yang lulus, apa yang belum dijalankan, dan penyimpangan dari rencana.

## Checklist manual (Fase A langkah 4)

| Area | Yang dicari | Petunjuk grep |
|:--|:--|:--|
| Guard command | Mutasi global dengan izin terlalu sempit (mis. `sync.view` untuk operasi yang menimpa data cloud) | baca body command yang memanggil `force_*`, `enqueue` massal |
| Outbox | `sync::enqueue(..., None)` (tulis tanpa revisi) pada jalur yang bisa memakai data basi; `let _ = sync::enqueue` yang menelan error | `grep -n "let _ = sync::enqueue"` |
| Android storage | Path `/storage/emulated/0/...` apa pun (aturan 28), termasuk salinan cadangan database | `grep -rn "/storage/emulated"` |
| Uang | `Decimal::from_f64_retain` (membawa galat biner: 0.3 menjadi 0.2999…, pembulatan berbeda dari Web), float untuk nominal | `grep -rn "from_f64_retain\|f64"` di `payroll/` |
| Panic Rust | `&s[a..b]` pada string, `len() - n` pada `usize` | regex `&[a-z_.]+\[[^\]]*\.\.` |
| Tanggal | `toISOString().slice(0, 10)` / `.split("T")[0]` dari "sekarang" (UTC, salah 00:00–07:00 WIB). Aritmetika kalender murni dari string `YYYY-MM-DD` aman | `grep -rn "toISOString()"` |
| Guard halaman | Halaman privat tanpa `canAccessArea` (aturan 36); di mobile pakai `router.replace`, bukan `redirect("/forbidden")` | loop semua `page.tsx` |
| Kamera | `await decodeFromConstraints` lalu `ref = controls` tanpa cek apakah sudah di-stop atau di-unmount | baca `startCamera` di `scanner/page.tsx` dan `mobile/src/components/ScannerView.tsx` |
| Race UI | `load()` async yang menulis state tanpa nomor urut ketika tab atau filter bisa berubah | `useCallback(async` + `set*` |
| Zod | Skema di `src/lib/server/operational/sync-schema.ts` lebih longgar dari CHECK constraint cloud di `turso.rs` (aturan 37) | bandingkan `grep "CHECK *("` dengan `z.enum` |
| UNIQUE | UNIQUE pada kolom bisnis tabel yang disinkronkan (aturan 32). UNIQUE yang dipakai sebagai target `ON CONFLICT` sinkronisasi memang disengaja | `grep -n UNIQUE storage.rs turso.rs` |

## Aturan & constraint

**Wajib:**
- Setiap temuan menyebut berkas:baris, alur kejadian konkret, dan aturan yang dilanggar (nomor dari `CLAUDE.md`).
- Temuan yang belum dibuktikan eksekusi atau kompilasi ditandai "belum diverifikasi".
- Edit Rust bersama hanya di `web-desktop/src-tauri/src/desktop/`, lalu `sync:mobile`.
- Perubahan yang melemahkan keamanan atau menghapus fitur wajib dikonfirmasi user.
- Urutan dokumen Rust: `/// doc` → `#[tauri::command]` → `pub fn` (aturan 45). Nama command khusus mobile berawalan `mobile_` (aturan 27).
- Laporan akhir menyebut dengan jujur gerbang yang TIDAK dijalankan (mis. "Rust belum dikompilasi").

**Dilarang:**
- Mengedit salinan hasil sync (`mobile/src/lib`, `mobile/src/types`, modul Rust mobile yang ada di daftar salin).
- Melonggarkan atau me-whitelist skrip audit (`audit-sync-contract.ts`, `schema-audit.ts`) supaya lulus (aturan 35).
- Menghapus command atau fungsi setelah hanya grep di `web-desktop/`.
- Menjalankan `cargo test` / `bun run check` penuh tanpa bertanya bila user pernah mengeluh soal lamanya.
- Melaporkan temuan hasil regex tanpa membaca kodenya. Skrip di `scripts/` menghasilkan kandidat, bukan vonis.
- Mengubah skema produksi (drop UNIQUE, rebuild tabel induk FK ber-`ON DELETE CASCADE`) tanpa persetujuan eksplisit.

## Contoh lengkap

**Input user:**
> Lakukan audit kode mendalam terhadap `web-desktop` dan `mobile`: sinkronisasi outbox, keamanan command Tauri, Android storage, frontend.

**Langkah model (ringkas):**
1. `audit:schema` lulus, `audit:contract` lulus, tsc bersih, `drift.ts` identik.
2. `command-guards.ts` menghasilkan `desktop_force_resync_settings -> require_permission("sync.view")`. Body-nya dibaca: memanggil `force_enqueue_settings`, yang mengantrekan shift, profil perusahaan, dan hari libur dengan `sync::enqueue(..., None)`.
3. `grep -rn "/storage/emulated"` menemukan `public_output_dirs()` yang dipanggil `export_database` di Android.

## Failure mode

1. **Menghapus kode yang ternyata dipakai platform lain.** Contoh nyata: `desktop_set_server_url` dihapus karena tidak dipanggil di `web-desktop`, padahal layar login mobile memakainya. Cegah dengan langkah 7: grep seluruh repo, terutama `mobile/src/app` dan `mobile/src/components`, sebelum menghapus. Bila dipakai, ganti penghapusan dengan guard.
2. **Perbaikan hanya mendarat di satu workspace.** Halaman mobile tidak disalin otomatis, jadi bug yang sama (tanggal UTC, race `load`, kamera bocor) tetap hidup di mobile. Cegah: untuk setiap perbaikan frontend, grep pola yang sama di `mobile/src/app` dan `mobile/src/components`.
3. **Menambah warning khusus target lain.** Contoh: `let mut dirs` yang di-`push` hanya di blok `#[cfg(not(target_os = "android"))]` menjadi `unused_mut` saat build Android, dan tidak terlihat di `cargo check` desktop. Cegah: hindari mutasi di dalam blok `#[cfg]`, pakai `if cfg!(...) { return ...; }` supaya kedua cabang dikompilasi di semua target.
4. **Melaporkan positif palsu sebagai temuan.** Skrip regex (guard, argumen IPC) dan asumsi ("halaman ini tanpa guard") sering keliru, misalnya halaman payroll mobile ternyata sudah memakai `canAccessArea`. Cegah: buka setiap berkas sebelum masuk tabel, dan cek juga lapisan pertahanan lain (CHECK lokal, guard di halaman).
5. **Mengklaim selesai tanpa kompilasi.** `check:quick` tidak mengompilasi Rust. Cegah: selalu jalankan `cargo check --tests` setelah mengedit Rust, dan sebutkan secara eksplisit gerbang yang dilewati (`cargo test`, uji manual aplikasi).
